# Source and model provenance

Four frozen entry points are archived independently; original A/B share neither an established model receipt nor a verified provider label. A has the two-stage stone interaction described by Dean as GLM's standout. That resemblance is not enough to label its provider as fact. B is the simpler implementation in the directory that also contains Codex's separate play.html entry. Keep the A/B port names until the exact launch/session receipt is provided.

Inspected files show Three.js imports/local vendoring. They do not establish copying a finished game repository. Provider/session-log recovery was blocked, so hidden provenance and historical token bills were not verified. Do not infer plagiarism from a good result or claim no reuse simply because none was found.

Prompt precision plausibly helped: the shared brief fixed role powers, perspective, platform, route, territory trigger, first-boss scope and win/loss. Simpler materials and fewer mechanics reduce failure surface; a visible two-stage rock action can create disproportionate game feel. These are engineering explanations, not a controlled causal result. No equal-seed/equal-budget or prompt-ablation experiment was run.

The new scene derives from the archived Web 6Pro edition. Combat/server, explicit tri-language UI, sound synthesis, shop and storage were authored directly for this iteration. Environmental stone identity is a new implementation of the observed design idea. No extra visual/audio asset purchase or new third-party game repository was used in this iteration.

Engine: Three.js r160 build reused from local original with MIT notice. This says nothing about the provenance of an AI model's training data. No private raw logs, credentials, or class recording are part of the release.
